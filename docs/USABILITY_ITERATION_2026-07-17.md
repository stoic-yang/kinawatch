# Dashboard 可用性迭代（2026-07-17）

本轮根据真实页面批注修正日期口径、离线数据表达、复盘顺序、分类语义
和 Kina 建议生成链。Dashboard 仍保持本地、只读和按需运行。

## 页面决策

- 页面固定使用 `06:00–次日 06:00` 作息日，不再暴露日历日/作息日按钮。
- 凌晨 `00:00–05:59` 的“今天”归入前一个作息日。
- 亮暗主题可在页头手动切换并保存在浏览器本地。
- 刷新按钮位于页头，只刷新当前作息日。
- 日记没有明确离线时间段时显示“未记录”，不把日历计划当作实际活动。
- 不展示分类覆盖率数字或解释文案。
- 复盘栏中自由记录位于 Kina 建议之前。

## 分类 v2

来源仍是 Kina：

`$KINA_ROOT/plugins/kina/config/activitywatch_categories.json`

规则从“按应用粗分”改为两层：

1. 优先根据标题识别具体上下文，例如课程、研究、工程、技术学习和娱乐。
2. 无法判断意图时，落入诚实的观察级类别：
   `AI 协作`、`文档/课件`、`网页浏览`、`系统/工具`。

因此桌面 ChatGPT、Claude、Codex 不再默认算作编码；带有明确上下文的
`ChatGPT - 矩阵代数`、`ChatGPT - 科研`仍分别进入课程和研究类别。

真实数据回放：

| 窗口 | 旧未分类 | v2 未分类 |
|---|---:|---:|
| 近 7 天 | 15.61h | 0h |
| 近 30 天 | 42.23h | 0.02h |

这不表示系统已经知道所有意图；工具级兜底只是明确表示“观察到了工具，
但没有足够证据推断具体目的”。

## Kina 建议 v2

- 证据优先级改为：当天自由记录 > 当天真实产物/决策/测试/卡点 >
  昨日承诺 > 日历与 ActivityWatch > 长期背景。
- 自动注入的插件推荐块、内置浏览器上下文和复盘 runner 自身会话不再
  进入 Codex 工作证据。
- 建议默认 3 条、最多 5 条；至少 2 条直接回应当天文字或当天具体工作。
- 长期研究 profile 只能在当天证据明确触发时使用。
- 历史日记不会被 Dashboard 自动重写；新规则用于后续生成或显式重生成。

## 验收

- Dashboard Python 测试、Gate 1 和前端生产构建必须通过。
- Kina 全量测试必须通过。
- 浏览器检查需覆盖：作息日归属、页头主题/刷新、无覆盖率文案、
  自由记录顺序、新分类标签、桌面与窄屏布局、控制台错误。
