# Frontend Design — 一天一页 (v8)

Owner: Fable（前端）。首版 2026-07-16；v3 视觉重做 2026-07-17；
v4 视觉精修、v5 周/月统计 2026-07-23、v6 回归单日视图 2026-07-29、
v7 时间线手动校正 2026-07-30、v8 常驻笔记 2026-07-31。
本文记录当前产品思路与实现决策，供后续迭代与交接使用。
被否决的旧 Dashboard 概念不是本设计的参考。

## 产品定位

一个本地活动回看界面：始终围绕“这一天”组织信息，跨日数据只作为日页面
内部的节律上下文，不再提供独立周/月页面：

1. **我的一天是怎么流动的？** → 24 小时节律带 + 「工作流」
2. **时间花在了什么上？** → 侧边栏分类 + 主要应用
3. **我留下了什么、接下来做什么？** → 笔记栏（常驻 / 日 / 周 / 月）

不做单一生产力分数（V1 边界）。

日期通过页头前后日按钮、左侧月历或节律日块切换，不提供键盘方向键交互。
页面启动时从 `/api/settings` 读取 calendar/routine 口径、
`routine_day_start` 与时区；routine 模式下，开始时间之前的“今天”
仍属于前一个作息日。

刷新语义：没有独立刷新按钮。选中的日期保存在 URL（`?date=`，今天不带
参数）；浏览器刷新会停留在当前日期。若为今天，首次加载自动带
`refresh=1` 重读数据源；历史日期走现有日级缓存。

## 用户明确决定（2026-07-17）

- **只有亮色模式**，无主题切换按钮，无深色 CSS。
- **离线活动模块整体不展示**：节律带无离线轨、摘要无离线项、
  章节不混入离线条目、复盘栏不显示未解析离线行。后端数据字段保留。
- **Kina 建议不展示**（长期未使用）。`journal.kina_advice` 数据保留，
  恢复展示只需在 ReviewPanel 加回一节。
- 不展示分类覆盖率数字。
- 不展示“最长专注”：ActivityWatch 的屏幕事件间隙无法区分思考、暂停与
  真正离开，短间隙切断出来的数值不适合作为专注指标。
- 移除独立“时间构成”栏；分类已由侧边栏承担，主要应用也移入侧边栏。

## 视觉（v6）

- 侧栏、画布与内容区统一使用纯白底色，仅靠发丝线、间距和极轻阴影建立层级；
  不再用大面积浅灰区分区域。红色只作为选中日、
  当前时刻和编辑动作的强调色，
  其他颜色只属于数据（分类色、记录绿点）。
- 避免卡片堆叠：只有当天时间概览使用一块纯白、轻微抬升的主表面；节律、
  工作流和复盘仍由留白与发丝线组织。周节律日块也保持白底，选中项仅用
  细描边和轻阴影确认位置。
- 顶层不显示日 / 周 / 月切换；复盘周期只存在于右侧复盘栏，跨日活动范围
  只存在于日页面内部的「节律」区。
  页头固定显示同一组 58×28px 逐日导航，不因日期切换发生横向跳动。
- 时间线与年度热力图的浮窗统一通过
  `ViewportTooltip` 挂载到 `body`：纯白表面、发丝边框、同一阴影和 10px
  圆角，正文使用近黑与两级灰。数据元素不再使用浏览器原生 `title`
  提示，避免系统黑色浮窗与产品浮窗并存；冗余提示直接删除，仍有精确数据
  价值的节律格改用同一产品浮窗。
- 系统无衬线字体（PingFang SC），数字 tabular-nums；日期标题约 31px/700；
  辅助文字提高对比度，不再用接近不可读的浅灰承载时间、空状态和操作。
- 分类色在 `src/lib/colors.ts` 固定映射 Kina 分类 id（亮度统一的
  中饱和色板），未知分类哈希落入色池。
- 无远程字体、无外部请求，符合隐私边界。

### v4 参考与取舍（2026-07-23）

- [Linear 视觉刷新](https://linear.app/now/behind-the-latest-design-refresh)：采用
  “侧栏降低存在感、主内容成为视觉重心”和更紧凑的分段控件，不照搬其暗色主题。
- [Things 设计说明](https://culturedcode.com/things/features/)：采用内容结构清楚、
  操作在需要时显形、留白宽松但不松散的原则，不引入玻璃或夸张动效。
- [Notion Calendar](https://www.notion.com/product/calendar)：借鉴时间信息“一眼可读”
  的优先级，把活动窗口和屏幕活跃收进概览标题区。
- [GitHub contributions](https://docs.github.com/en/account-and-profile/concepts/contributions-on-your-profile)：
  年度视图继续使用稳定阈值的二维热力日历，不把颜色包装成生产力分数。
- 明确不恢复已否决的鼠标追随光晕、动态背景或大面积渐变；精致感来自层级、
  对齐、字重、对比、圆角与克制反馈。

### 动效（2026-07-17 打磨轮）

- 设计令牌集中在 `:root`：`--surface`（纯白表面）、`--ease`
  （cubic-bezier(0.25,0.6,0.3,1)）、`--t-fast: 130ms`、`--t-med: 220ms`。
- 所有交互元素（按钮、月历格、分类行、周卡片、分段开关、编辑动作等）
  统一 130ms 背景/文字/边框/阴影过渡；热力格与年热力格用 220ms 底色过渡。
- 切换日期时主内容 `.day-content`（key=日期）整体 220ms fade-rise 重入；
  编辑器与悬浮提示分别有 180ms/120ms 的进场动画。
- 时间线的当前时刻红线以 2.8s 周期做轻微呼吸（opacity 1→0.45）。
- 全局 `prefers-reduced-motion: reduce` 时关闭所有动画与过渡。
- 焦点环统一为低特异性的红色半透明 outline（`:where(...):focus-visible`），
  组件级 outline 优先生效。

## 实现决策

- React 19 + TypeScript + Vite，原生 SVG，无图表库、无运行时依赖。
- 会话切分、Top 应用均为**客户端展示层派生**（`src/lib/sessions.ts`），
  后端 timeline 保持权威。
- `src/api.ts` 只保留当前单日界面实际消费的响应字段；
  `docs/fable-api-types.ts` 继续记录后端完整接口契约。
- 时间线显示块保留 `event_refs`，点击后才调用
  `GET /api/activity/inspect`。活动编辑器在桌面端是右侧抽屉，在窄屏上占满
  视口宽度；普通点击与 Enter / Space 都能打开，只有移动超过阈值后才由
  时间线捕获指针用于平移。保存要求原始事件指纹与校正层 revision 同时匹配，
  结果只进入 KinaWatch 校正层并立即刷新当日；成功后提供一次显式撤销。
  分类可跟随规则、选用现有项或新建一个手动分类，但不修改全局 JSON 规则。
- dev 通过 Vite proxy 访问 `/api`；生产形态由 Python 后端同源托管
  `dist/`（见 `docs/BACKEND_RESPONSE_V1.md`）。
- 日记 Markdown 用极小的自研渲染（标题/段落/列表/待办/wikilink/粗体/行内代码），
  不引入完整 Markdown 库；wikilink 仅样式化不跳转。
- 常驻笔记由 `GET/PUT /api/journal/permanent` 读取和显式保存完整 Markdown；
  文件路径只来自本地配置，默认 `incoming.md`。读取不创建文件，保存携带文件
  指纹并使用同一套锁、同目录临时文件、原子替换和冲突拒绝。界面只在用户进入
  “常驻”页签后读取，预览中的待办框只表达 Markdown 状态，不会自动保存或
  直接改写文件。
- 新生成的工作流描述以可移植 Markdown Callout 保存在当日日记；Obsidian 中会
  原生渲染为默认收起的 Callout：

  ```markdown
  > [!abstract]- 工作流
  > **08:59–09:18**
  > 刚起床看了一眼 Dashboard 实现的情况。
  >
  > **09:36–11:35**
  > 继续完善 Dashboard。
  ```

  当天只有一个可收展的「工作流」Callout；每段描述以加粗时间段分隔，正文可
  自然扩展为多行 Markdown，不再生成多个并列 Callout 或视觉上独立的块 ID。
  每条的开始时间是稳定关联键，结束时间只用于阅读。页面读取时保存日记
  指纹，用户点击保存后调用 `PUT /api/journal/workflow`；后端只允许创建或
  替换该开始时间对应的条目，并用版本冲突检查、单笔记锁、同目录临时文件
  和原子替换保护其他内容。块重复或文件已变化时返回冲突，页面保留草稿，绝不
  静默覆盖。一次显式保存会把所选日记中所有已识别工作流描述原文保留并合并到
  这个总块，但不会修改其他日记区域或其他日期。解析器继续兼容此前带
  `^workflow-HHMM` 锚点的多个 Callout、单行列表格式，以及曾由 Dashboard 生成的
  完整 `-+**工作流+...+^workflow-HHMM` 异常签名；只有用户明确保存的目标块
  所在日记才会迁移，不建立浏览器本地事实源。
- 日复盘正文使用一个默认收起、标题为「复盘」的 `abstract` Callout，内部
  以加粗字段标题容纳「我的总结 / 今日产出 / 明天的计划 / 自由记录」。四个字段仍各自
  就地编辑，保存调用 `PUT /api/journal/review` 并携带页面读取时的文件指纹；
  409 时保留草稿，不静默覆盖。内部字段 `next_action` 保持 API 兼容；旧
  「明日第一步」Callout 和二级标题继续只读兼容，仅在用户显式保存对应字段时
  归并。历史 `## 自由记录` 也可在显式保存时归并；其他未结构化正文、Kina 生成内容与
  其他日记区域不属于网页编辑范围。未结构化正文虽然保持原位且不属于写入范围，
  但在界面上与受控 `freeform_markdown` 共同归入同一个「自由记录」区块，不再
  单独显示只读正文区。旧 `完成复盘` 勾选不再显示或参与状态判断。
- 复盘栏的周 / 月模式分别读取当前日期所在的 `YYYY-Www` 与 `YYYY-MM`，
  只展示和显式保存一个 `自由记录` 字段。读取不创建文件；保存继续使用接口返回的
  指纹、单笔记锁和原子替换，缺失笔记仅在用户点击保存时创建。周期切换不改变
  页面 URL、日期、时间线、节律与工作流。
- 两种年视图只在用户主动进入时加载；前端调用现有 `/api/range`，采用
  14 天分片并按最近日期优先、限制为 3 路并发。后端会把每个分片中尚未缓存的
  日期合并为每个 ActivityWatch bucket 一次 REST 读取，避免逐日网络往返；
  首批返回前使用与正式七行网格同形的绿色渐变扫光；
  任一分片完成后立即保留已返回的真实格并只对尚未返回的历史日期继续扫光，
  不等待全部 365 天完成；
  精确进度通过无障碍状态播报，系统要求减少动态效果时停用动画。近一年请求截至今天的 365 天；自然年只
  请求该年 1 月 1 日至今天（或历史年年末），但保持完整 Jan–Dec 网格。
  两者复用日级缓存，不新增年度聚合接口，也不会让普通单日页面扫描全年数据。
## 已知取舍 / 下一迭代候选
