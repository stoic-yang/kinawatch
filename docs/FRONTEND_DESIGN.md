# Frontend Design — 「一天一页」 (v3)

Owner: Fable（前端）。首版 2026-07-16；v3 视觉重做 2026-07-17。
本文记录当前产品思路与实现决策，供后续迭代与交接使用。
被否决的旧 Dashboard 概念不是本设计的参考。

## 产品定位

一个**单日复盘面板**：打开就是"今天这一页"，回答三个复盘时的
自然问题，而不是罗列指标：

1. **我的一天是怎么流动的？** → 24 小时节律带 + 「工作流」
2. **时间花在了什么上？** → 侧边栏分类 + 主要应用
3. **我留下了什么、明天做什么？** → 复盘栏（日记结构化内容）

不做单一生产力分数（V1 边界）。

## 信息架构

```
Sidebar   左侧可收起（macOS 分栏面板图标，状态存本地；收起后保留独立窄栏）：
          - 月历（不重复显示年月，年月与星期由主日期标题承担；顶部只保留
            靠右的前后月导航与收起控制；导航使用按按钮中心绘制的细线箭头；周一起始，日期交互面
            统一为 28×28px 正方形；有用户记录的日期带绿点，
            今天红字，选中红底白字，
            未来日禁用；前后箭头切月，月度记录索引按月懒加载并缓存）
          - 主要分类（按当日时长显示前 6 类）：色点 + 名称 + 当日时长，
            点击隐藏/显示；隐藏集合存本地；隐藏的分类从节律带、
            工作流、主要应用中全部过滤（后端概览数字不受影响）；
            有隐藏时出现"全部显示"
          - 主要应用（Top 6 应用 + 当日时长，跟随分类筛选结果）
Header    日期标题（粗体月日 + 次级年份、ISO 周数与星期）
Overview  紧凑日期栏下，「时间线」标题行内只保留活动窗口 · 屏幕活跃；
          24h 单轨节律带支持滚轮/触控板缩放、拖动平移、双击复位，
          不显示额外缩放按钮（屏幕活动按分类着色，悬停显示块
          详情，今日显示当前时刻红线）；轨道使用可响应式拉伸的 SVG，
          时间刻度由 SVG 外的 HTML 轴承载，避免非等比 `viewBox` 缩放
          同时拉伸数字字形
Rhythm    时间线之后的「节律」上下文区（位于工作流/复盘两栏之前，可整体
          收起，收起状态通过 localStorage 持久化）：标题行左为可点击的
          「节律」标题，右为同一组等宽分段按钮，支持“近七天 /
          自然周 / 近一年 / 2026年”，最后一项进入完整自然年。当前只有
          2026 年，后续出现更多年份时才在该组旁显示前后年份切换，
          不使用单选下拉框。自然周可前后切换周数；日块可点击切到对应
          日期。七日模式每天以横向 24 格热力条表达 06:00–次日 06:00 的
          活动分布，并显示总时长与活动窗口；年度视图在标题
          行右侧显示加载进度与累计。不再显示“日均/日复盘”摘要行；
          日页面不再插入额外的「本周」状态卡片或周复盘入口。
          近一年与自然年模式均以周为列、周一至周日为行，采用 GitHub 式绿色热力图
          表达每天的屏幕活动时长；图表从内容起点自然铺开，格子随可用宽度舒展，
          不再用居中的固定宽度小表格，也不显示拥挤的星期侧标；实际日期范围紧跟
          当前选中的「近一年 / YYYY年」控件，不再孤立放在图表底部；图表底部不再
          显示重复的时长口径或“少—多”色阶图例，格子颜色继续使用
          固定时长阈值（0、<2h、<4h、<7h、>=7h），不按相对排名制造
          “生产力”结论。格子可点击切到当天，悬浮或键盘聚焦时以单行即时显示日期与
          精确屏幕活跃时长；自然年固定展示 1 月 1 日至
          12 月 31 日，未来日期只保留月份坐标和布局占位、不绘制空框也不可点击，
          同样不会发起未来数据请求；
          窄屏在图内横向滚动并自动定位所选日期
Columns   两栏无卡片、留白分区，栏首为细分隔线标题：
          左：工作流（>15min 间隔切分的屏幕会话，每节含时段、
              时长、Top 应用、分类构成细条；每段可在页面内新增或编辑描述，
              用户显式保存后通过同源受限 API 同步到当日日记并立即重读；
              已有描述不再重复显示类型标签，正文与编辑入口共用同一行）
          右：复盘（本地 provider 显示“KinaWatch 本地存储”；Obsidian provider
              在已有日记时显示打开链接；标题行不重复显示
              “已复盘 / 未复盘”状态；我的总结 / 今日产出 / 明天的计划 / 自由记录均可
              在页面内新增和编辑，计划编辑区支持更充分的多段 Markdown，
              用户显式保存后同步进当日日记的同一个「复盘」Callout；首次
              保存可创建缺失日记，本地 provider 完全不要求安装或打开 Obsidian；
              空状态不显示实现目录路径；
              内容含我的总结 / 今日产出 / 明天的计划 / 自由记录 /
              一天活动小总结(折叠)，空节显示引导文案；复盘标题之后直接进入
              当日复盘内容，不重复展示一周日期状态。周复盘幂等 API 继续保留，
              但当前页面不提供入口）
Warnings  仅在数据来源、日记解析或重叠出现实际异常时显示；正常页面无底栏
```

日期通过左侧月历或周节律日块切换，不提供前后日按钮或键盘方向键交互。
固定使用作息日口径（06:00–次日 06:00）；凌晨 00:00–05:59 的“今天”
仍属于前一个作息日。

刷新语义：没有独立刷新按钮。选中的日期保存在 URL（`?date=`，今天不带
参数），浏览器刷新会停留在当前查看的日期；如果该日期是今天，首次加载
自动带 `refresh=1` 重读数据源，历史日期走缓存。

## 用户明确决定（2026-07-17）

- **只有亮色模式**，无主题切换按钮，无深色 CSS。
- **离线活动模块整体不展示**：节律带无离线轨、摘要无离线项、
  章节不混入离线条目、复盘栏不显示未解析离线行。后端数据字段保留。
- **Kina 建议不展示**（长期未使用）。`journal.kina_advice` 数据保留，
  恢复展示只需在 ReviewPanel 加回一节。
- 不展示分类覆盖率数字。
- 不展示“最长专注”：ActivityWatch 的屏幕事件间隙无法区分思考、暂停与
  真正离开，短间隙切断出来的数值不适合作为专注指标。
- 移除独立“时间构成”栏；分类已由侧边栏承担，主要应用也移入侧边栏。

## 视觉（v3）

- 白底、近黑文字、灰阶界面；红色作为选中日、当前时刻和编辑动作的强调色，
  其他颜色只属于数据（分类色、记录绿点）。
- 无卡片边框：分区靠留白 + 发丝线（#EDEDEB），轨道灰 #F4F4F2。
- 系统无衬线字体（PingFang SC），数字 tabular-nums；日期标题 30px/700。
- 分类色在 `src/lib/colors.ts` 固定映射 Kina 分类 id（亮度统一的
  中饱和色板），未知分类哈希落入色池。
- 无远程字体、无外部请求，符合隐私边界。

### 动效（2026-07-17 打磨轮）

- 设计令牌集中在 `:root`：`--surface`（浅面色）、`--ease`
  （cubic-bezier(0.25,0.6,0.3,1)）、`--t-fast: 130ms`、`--t-med: 220ms`。
- 所有交互元素（按钮、月历格、分类行、周卡片、分段开关、编辑动作等）
  统一 130ms 背景/文字/边框/阴影过渡；热力格与年热力格用 220ms 底色过渡。
- 切换日期时主内容 `.day-content`（key=日期）整体 220ms fade-rise 重入；
  编辑器与悬浮提示分别有 180ms/120ms 的进场动画。
- 时间线的当前时刻红线以 2.8s 周期做轻微呼吸（opacity 1→0.45）。
- 全局 `prefers-reduced-motion: reduce` 时关闭所有动画与过渡。
- 焦点环统一为低特异性的红色半透明 outline（`:where(...):focus-visible`），
  组件级 outline 优先生效。

## 实现决策

- React 19 + TypeScript + Vite，原生 SVG，无图表库、无运行时依赖。
- 会话切分、Top 应用均为**客户端展示层派生**（`src/lib/sessions.ts`），
  后端 timeline 保持权威。
- 类型定义 `src/api.ts` 手工镜像 `docs/fable-api-types.ts`。
- dev 通过 Vite proxy 访问 `/api`；生产形态由 Python 后端同源托管
  `dist/`（见 `docs/BACKEND_RESPONSE_V1.md`）。
- 日记 Markdown 用极小的自研渲染（段落/列表/wikilink/粗体/行内代码），
  不引入完整 Markdown 库；wikilink 仅样式化不跳转。
- 新生成的工作流描述以可移植 Markdown Callout 保存在当日日记；Obsidian 中会
  原生渲染为默认收起的 Callout：

  ```markdown
  > [!abstract]- 工作流
  > **08:59–09:18**
  > 刚起床看了一眼 Dashboard 实现的情况。
  >
  > **09:36–11:35**
  > 继续完善 Dashboard。
  ```

  当天只有一个可收展的「工作流」Callout；每段描述以加粗时间段分隔，正文可
  自然扩展为多行 Markdown，不再生成多个并列 Callout 或视觉上独立的块 ID。
  每条的开始时间是稳定关联键，结束时间只用于阅读。页面读取时保存日记
  指纹，用户点击保存后调用 `PUT /api/journal/workflow`；后端只允许创建或
  替换该开始时间对应的条目，并用版本冲突检查、单笔记锁、同目录临时文件
  和原子替换保护其他内容。块重复或文件已变化时返回冲突，页面保留草稿，绝不
  静默覆盖。一次显式保存会把所选日记中所有已识别工作流描述原文保留并合并到
  这个总块，但不会修改其他日记区域或其他日期。解析器继续兼容此前带
  `^workflow-HHMM` 锚点的多个 Callout、单行列表格式，以及曾由 Dashboard 生成的
  完整 `-+**工作流+...+^workflow-HHMM` 异常签名；只有用户明确保存的目标块
  所在日记才会迁移，不建立浏览器本地事实源。
- 日复盘正文使用一个默认收起、标题为「复盘」的 `abstract` Callout，内部
  以加粗字段标题容纳「我的总结 / 今日产出 / 明天的计划 / 自由记录」。四个字段仍各自
  就地编辑，保存调用 `PUT /api/journal/review` 并携带页面读取时的文件指纹；
  409 时保留草稿，不静默覆盖。内部字段 `next_action` 保持 API 兼容；旧
  「明日第一步」Callout 和二级标题继续只读兼容，仅在用户显式保存对应字段时
  归并。历史 `## 自由记录` 也可在显式保存时归并；其他未结构化正文、Kina 生成内容与
  其他日记区域不属于网页编辑范围。旧 `完成复盘` 勾选不再显示或参与状态判断。
- 两种年视图只在用户主动进入时加载；前端调用现有 `/api/range`，每段最多
  31 天并按最近日期优先、限制为 3 路并发。首批返回前使用与正式七行网格同形的绿色渐变扫光；
  任一分片完成后立即保留已返回的真实格并只对尚未返回的历史日期继续扫光，
  不等待全部 365 天完成；
  精确进度通过无障碍状态播报，系统要求减少动态效果时停用动画。近一年请求截至今天的 365 天；自然年只
  请求该年 1 月 1 日至今天（或历史年年末），但保持完整 Jan–Dec 网格。
  两者复用日级缓存，不新增年度聚合接口，也不会让普通单日页面扫描全年数据。

## 已知取舍 / 下一迭代候选

- “最长专注”后端兼容字段不再作为产品指标展示。
- 桌面侧边栏在 `<=900px` 时直接隐藏；移动端目前没有月历和分类筛选入口。
- 无搜索、无分类规则编辑入口。
- 工作流描述已支持在 Dashboard 内新增、修改并写入当前 local/obsidian
  provider；当前不支持删除描述，空内容无法保存。
- 离线活动与 Kina 建议的数据链路完整保留在后端与 API 中，
  前端按用户决定隐藏；恢复均为纯前端改动。
